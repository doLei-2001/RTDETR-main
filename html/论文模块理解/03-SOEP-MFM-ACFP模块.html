🏗️ SOEP-MFM / ACFP: 自适应协同融合金字塔

解决特征金字塔传播过程中小目标信息逐级退化的问题，构建从P2到P5的跨尺度特征保护链

从问题出发：为什么需要改进特征金字塔？

🔴 核心问题：P3层分辨率不足以保留小目标细节

RT-DETR仅使用P3(1/8)、P4(1/16)、P5(1/32)三层特征图。对于远距离小目标：

  • 原图仅占3-10像素的小目标，在P3层已压缩至不足1个像素
  • 缺乏P2(1/4)高分辨率特征层的引入
  • CCFM的固定权重融合 → 无法自适应调整各层贡献
  • 小目标特征在金字塔传播中逐级退化

❌ 简单引入P2的问题

  • 直接加P2检测头 → 计算量暴增（特征图大4倍）
  • 传统下采样再次引入采样混叠
  • 参数量增加23.1%，计算量增加57.2%
  • 后处理更耗时

✅ SOEP/ACFP的解决思路

  • SPDConv（空间-深度卷积）→ 无损降维
  • MFM（互促融合模块）→ 自适应加权替代Concat
  • CSP-OmniKernel → 多尺度增强
  • 不加P2检测头，只在融合阶段引入P2特征

🎯 答辩要点："Baseline的CCFM仅使用P3、P4、P5三层特征图进行融合，P3的1/8分辨率已不足以保留小目标的像素细节。而且CCFM采用简单的通道拼接进行融合，这种固定权重的方式无法根据场景中目标尺度的分布动态调整各层特征的贡献度。直接添加P2检测头虽可引入高分辨率信息，但特征图扩大4倍导致计算量暴增57.2%。因此，我提出了ACFP：使用SPDConv将P2特征无损映射至P3空间，在零信息损失的前提下引入细粒度特征；使用MFM自适应加权替代传统Concat，使网络能根据场景内容动态调整各层特征的贡献度；同时引入CSP-OmniKernel多尺度增强模块，进一步增强融合后特征的判别能力。"

💡 SOEP的核心创新

SOEP不再简单地添加P2检测头，而是将P2特征通过SPDConv无损降维后注入P3融合层，从而在不增加P2检测计算量的前提下，将小目标的细粒度信息有效注入特征金字塔。同时用MFM替代传统Concat实现自适应权重融合。

SPDConv：空间-深度卷积（无损下采样）

原图 H×W
一个像素都不丢
↓ 2×2分块重排
4通道 H/2×W/2
空间 → 通道维度
↓ 1×1 Conv降维
输出 C'×H/2×W/2
信息零损失
SPDConv的核心思想：
将空间维度的像素无损映射至通道维度，避免步长卷积的信息丢失。

以2×2空间块为例：4个相邻像素被重排为4个通道，所有原始像素值被完整保留，没有任何信息被丢弃。
📂 查看代码
# SPDConv: 空间到深度卷积（Space-to-Depth + Conv） class SPDConv(nn.Module): def __init__(self, inc, ouc): self.conv = Conv(inc * 4, ouc, k=3) # 拼接后卷积降维 def forward(self, x): # 将空间4个相邻像素 → 通道维度 # 相当于把H×W切成四个子图，然后叠在一起 x = torch.cat([ x[..., ::2, ::2], # 左上 x[..., 1::2, ::2], # 左下 x[..., ::2, 1::2], # 右上 x[..., 1::2, 1::2] # 右下 ], 1) # [B, 4C, H/2, W/2] x = self.conv(x) # [B, C_out, H/2, W/2] return x

MFM：互促融合模块（Mutual Promotion Module）

💡 为什么需要MFM？

传统特征融合使用通道拼接（Concat），隐式假设各层特征同等重要。但在自动驾驶中，不同尺度特征对检测的贡献不同——低层特征对密集小目标更重要，高层特征对大目标更关键。MFM通过注意力机制为每一路特征动态分配通道级权重。

🎯 MFM与传统Concat的区别

对比项传统ConcatMFM
融合方式通道维度拼接加权求和（注意力融合）
权重分配固定（无）自适应（从数据学习）
对场景适应性对任何输入一样处理根据场景内容动态调整
特征交互被动堆叠不交互先sum再生成权重
📂 查看MFM代码
# MFM: 互促融合模块 class MFM(nn.Module): def forward(self, in_feats_): # 1. 通道对齐（1×1 Conv将各输入通道统一） in_feats = [layer(f) for f, layer in zip(in_feats_, self.conv1x1)] # 2. 堆叠 → 求和 → GAP + MLP → Softmax权重 in_feats_stack = torch.cat(in_feats, dim=1) # [B, 3C, H, W] in_feats_stack = in_feats_stack.view(B, 3, C, H, W) feats_sum = torch.sum(in_feats_stack, dim=1) # 汇总信息 # 3. 生成每个特征图的通道级权重 attn = self.mlp(self.avg_pool(feats_sum)) # [B, 3C, 1, 1] attn = self.softmax(attn.view(B, 3, C, 1, 1)) # 归一化 # 4. 加权融合 out = torch.sum(in_feats_stack * attn, dim=1) # [B, C, H, W] return out

CSP-OmniKernel：多尺度特征增强

💡 为什么需要OmniKernel？

经过MFM融合后的特征虽然实现了跨尺度自适应融合，但在密集小目标场景中，小目标仍易被复杂背景噪声淹没。OmniKernel通过从全局到局部的多尺度特征学习，进一步增强特征的判别能力。

OmniKernel 三路并行分支
🌐 全局分支

GAP + 1×1 Conv + broadcast
场景级语义 → 全局指引
(判断密集/稀疏场景)

🔲 大核分支

31×31 + 1×31 + 31×1 DWConv
超大感受野（各向异性）
捕捉车道/路口等大范围结构

🔍 局部分支

1×1 DWConv
保持原始局部特征
保留小目标高频纹理

FCA频域通道注意力 → FFT → 通道加权 → IFFT → SCA空间通道注意力 → GAP → 1×1 → 广播 → FGM频域门控
CSP结构（部分通道处理，降低计算量）

仅25%通道经过OmniKernel处理，75%直接恒等映射。既利用了OmniKernel强大的多尺度表达能力，又将计算量控制在可接受范围内。

📂 查看CSP-OmniKernel代码
# CSPOmniKernel: 部分通道处理 + OmniKernel class CSPOmniKernel(nn.Module): def __init__(self, dim, e=0.25): self.e = e # 25% 走OmniKernel self.cv1 = Conv(dim, dim, 1) self.cv2 = Conv(dim, dim, 1) self.m = OmniKernel(int(dim * self.e)) def forward(self, x): # 通道分割：25% 走OmniKernel, 75% 直接通过 ok_branch, identity = torch.split( self.cv1(x), [int(x.size(1) * self.e), int(x.size(1) * (1 - self.e))], dim=1) return self.cv2(torch.cat((self.m(ok_branch), identity), 1))

ACFP的三个改进

  • SPDConv模块：将P2特征无损映射至P3空间
  • MFM模块：自适应加权替代传统Concat
  • CAFE模块（CSP-OmniKernel）：多尺度特征增强

优势总结

  • 不增加P2检测头 → 避免计算量暴增
  • 无损特征传递 → 小目标信息持续保护
  • 自适应融合 → 场景自适应权重分配
  • 部分卷积 → 控制计算量，25%处理

✅ 本章核心结论

  • SOEP-MFM/ACFP通过P2低损引入 + 自适应加权 + 多尺度增强，有效解决了特征金字塔传播中的小目标信息退化问题
  • SPDConv确保了从CAS-FD到ACFP的无损特征流连续性
  • MFM的自适应权重使模型能根据场景内容动态调整各层特征的贡献
  • CSP-OmniKernel的部分通道策略在增强特征的同时控制计算成本
  • 与CAS-FD形成完整的特征保护链：源头保护(Stage1) → 传播保护(Stage2)
